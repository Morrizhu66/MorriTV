# HFSY 图像与视频模型接入设计

## 目标

在保留现有 Ark / Seedream / Seedance 链路的前提下，将 HFSY 作为独立供应商接入，新增 GPT Image 2、GPT Image 2 Pro、Nano Banana 2、Nano Banana 2 Pro 和 Minimax H3 五个模型选项。

## 架构

新建 `hfsy_client.py` 承担 HFSY 协议差异：模型目录、请求构造、HTTP 调用、异步轮询、结果 URL 解析和本地文件上传。`server.py` 仍负责本地任务队列与历史，根据 profile 将 HFSY 任务交给新客户端，不改动旧的 Ark 子进程调用。`app.js` 使用声明式模型目录渲染选项，并按模型限制参考素材类型、数量、比例、清晰度和时长。

## 数据流

表单提交展示名对应的稳定 profile ID。服务端先根据模型元数据校验提示词和素材，再调用对应的图片或视频接口。HFSY 生成接口只接受公网可访问的参考素材 URL；官网创作中心的上传端点已实测只接受网页登录 token，因此本地 HFSY 文件上传会在扣费前被阻止。同步返回结果时直接完成任务；返回 task ID 时在后台轮询到 `SUCCESS` 或 `FAILURE`。图片结果下载到 `results/`，视频保留返回 URL 供播放。

## 安全与失败处理

HFSY 密钥只从 `HFSY_API_KEY` 环境变量或已忽略的 `.env` 读取，不进入源码、任务历史和前端响应。HTTP 错误、非法 JSON、远程失败状态和轮询超时都转成可读的本地任务错误。Minimax H3 严格限制为图片最多 5 张、音频最多 1 条、不允许视频参考、提示词最多 2000 字且时长 5–15 秒。

## 验证

自动测试覆盖模型目录、三类请求体、结果解析、后端路由、参数限制、前端选项和密钥不泄漏。最后运行全量 unittest、语法检查、本地 HTTP 冒烟验证，并使用真实 HFSY 密钥至少完成一次低成本图片生成。
