# 豆包真人验证调研与任务终止

调研日期：2026-10-24。这里的“真人检测”按网页验证码／人机验证理解。没有拿到本次验证码画面、触发日志或豆包内部风控规则，无法确定本次触发原因。

## 结论

市面上有减少浏览器自动化特征暴露的工具，但没有找到它们稳定通过豆包验证的可信证据。不要把某个工具的通用宣传当成豆包上的成功率。

## 当前实现与建议

代码已经使用可见 Chrome、独立持久 profile、单并发与 pending 记录，连接中断后只查询原任务。当前没有证据表明应该更换这些基础方案。建议保持它们，并避免失败后自动反复提交；若继续优化，应先记录验证出现的阶段、提示与请求间隔，再评估降低提交频率或增加人工接管的效果。这里是工程建议，不是已验证的豆包风控规律。

本次新增的「终止任务」支持豆包排队、执行中、查询暂停、失败任务：

- 停止本地连接器，阻止原任务恢复和迟到结果回填，状态持久保存为“已终止”。
- 仅归档对应任务的 pending 记录，保留登录 profile；原会话记录清除，下一次提交使用新会话，防止混入旧结果。
- 保留原提示词、参考素材和历史记录；新的生成由用户明确发起。
- 当前网页连接器没有可确认的上游取消协议，因此本地终止不保证豆包服务器上的任务停止，也不保证退还额度。

## 验证范围

通过本地真实子进程验证执行中终止、成功返回和超时回收；通过隔离 HTTP 服务验证取消接口及终止后拒绝恢复；覆盖重启恢复、取消后再次提交以及前端动作。没有提交付费生成，也没有实测豆包真人验证的触发率或绕过成功率。
